# YouTube 内容通道探测

更新于 2026-08-22 · 记录者 AI

## 目的

验证“能拿到的内容就分析，拿不到的先保留入口”是否可以落成可观察的多通道流程。此次只做单视频探测，不批量撞击 YouTube，也不把字幕全文写入仓库。

## 实测结果

| 通道 | 结果 | 结论 |
| --- | --- | --- |
| YouTube Data API | 无凭据请求返回 HTTP 403：需要 API Key 或其他 API consumer identity | 官方 API 路径存在，但当前环境没有 `YOUTUBE_API_KEY`；这次不是配额耗尽 |
| 公开频道页 | GMTK 频道页可读，并可解析出频道 ID | 可作为低频发现入口，但页面结构不应当作稳定 API |
| 公开频道 RSS | `feeds/videos.xml` 对 GMTK 返回 404 | 当前不能把 RSS 当作可靠主通道 |
| `yt-dlp` | 隔离虚拟环境安装 `2026.08.19`；单条视频可列出并下载英文自动字幕 | Downloader 不是完全不可用，问题主要在批量频率、通道状态和退避 |
| `youtube-transcript-api` | 对同一视频单请求成功，得到 16,839 个去重后字符 | 现有涓流脚本的字幕通道仍可用，不应因批量失败判定为不存在 |

探测视频为 GMTK 的 [Why Does Celeste Feel So Good to Play?](https://www.youtube.com/watch?v=yorTG9at90g)。`yt-dlp` 发现英文与简体中文字幕轨道，并在仓库外临时目录取得英文 VTT；字幕内容讨论移动参数、跳跃曲线、攀爬耐力、冲刺动量、动画与输入反馈、coyote time、碰撞容错、速通技巧和迭代取舍。

现有 Work Item `a-022-why-does-celeste-feel-so-good-to-play` 的 `summary` 与 `whyRelevant` 与这次字幕抽样核对一致，因此本次不重复改写资源数据。验证结果说明：资源不是只能做链接聚合；有文本证据时可以生成带能力／主题映射的内容分析。

## 当前策略

1. 继续使用每轮一条、四小时触发和通道失败后 24 小时退避的涓流脚本；不手动清除冷却，不把 `SKIP` 写成成功。
2. 将 `youtube-transcript-api` 作为现有低频主通道；`yt-dlp` 作为单条低频备用入口，不在同一次失败后立即双重重试。
3. 官方 API 先用于元数据发现和增量同步。真正运行它需要把凭据通过环境变量提供，不能把 key 写入仓库；字幕 API 另有 OAuth 权限和政策约束。
4. 无法取得文字稿时仍保留视频 URL、来源和事实元数据，但不生成假摘要；有创作者提供的文字稿、描述、章节或对应文章时再进入分析层。

## 不确定性

本次只验证了一个公开视频和一个频道，不代表所有频道都具有相同字幕可用性或网络结果。字幕缓存、失败状态和模型输出继续放在仓库外；当前仍有冷却中的历史队列，不能用本次单条成功推断批量抓取已经安全。
