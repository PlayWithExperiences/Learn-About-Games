# 学习路径关注面的证据审计

2026-08-16

## 背景

用户指出，一条书、课程或演讲可能同时涉及玩法、美学、实现和研究；问题不在于标签数量多，而在于标签是否真的由内容支持。原有路径关注面已经允许重叠，但缺少可回溯的证据结构，也会把没有命中标签的条目静默放进“跨支柱”。

## 决策

本轮先做一条窄切片，而不是声称完成全目录语义审校：审计“手感与反馈”路径实际精选的 100 条 Work Item。关注面仍然可以有多个，但每个关注面都必须至少对应一个该 Work Item 自己的 `capabilityIds` 或 `knowledgeTopicIds`；不继承资源主题集合的描述性能力，也不使用标题关键词替代标签证据。`focusEvidence` 会把命中的 ID 原样带到路径模型中，便于后续人工复核。

语义校正了两个容易过拟合的映射：`player-perspective-taking`（玩家视角转换）用于研究与验证，不再单凭“玩家”一词归入叙事；`experience-framing`（体验目标建构）也不再自动视为叙事能力。跨支柱只在玩法、叙事、美学三条核心支柱都拥有直接证据时生成。

## 结果

100 条精选资料的关注面分布为：玩法与挑战 98、叙事与表达 3、美学与表现 93、技术与实现 6、研究与验证 50、跨支柱 1。0 条没有可审计关注面，0 条把 `player-perspective-taking` 作为叙事证据。数量不是质量分，也不意味着每个标签都已经经过人工阅读全文；这是把归类从“看起来相关”推进到“能指出直接元数据依据”的第一轮。

## 限制与下一步

阶段排序仍使用独立的策展相关性评分（能力、知识主题、媒介和标题／摘要关键词），它不决定关注面归类。目录其余资源尚未完成同等规模的人工语义审计；付费或摘要型行业页面尤其需要后续逐条复核。下一步应保留 `focusEvidence` 的审计接口，继续抽查高风险多标签条目，并在有明确证据时补充或删除映射，而不是为了均衡数量强行加标签。

验证：路径单元测试 7/7；路径 Chromium 与移动端 E2E 10/10；`npm run check` 0/0/0。预览继续使用 `http://127.0.0.1:4321/Learn-About-Games/resources/paths/game-feel/`，本轮不推送或部署。
