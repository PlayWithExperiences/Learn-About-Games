# Devlog 003：v0.2 为什么改成知识网络

- 日期：2026-08-09
- 阶段：v0.2 发布验收

## M0 暴露了什么

M0 证明静态数据契约、GitHub Pages 子路径和一条完整学习切片可以工作，但它还不像最终想做的产品：能力地图是一组彼此分开的卡片；唯一的职业画像只在卡片底部加了很小的文字；资源库只有两条 Playtest 内容；Atlas 更像一组分开的例子，而不是能从时间和关系上探索的网络。

更重要的是，“精选路径”“已审核资源”和站内评分会要求维护者替所有用户作出很重、很主观的判断。不同人的背景、目标和时间无法被一条标准路径复制。v0.2 因此把产品主张收窄为三件可持续的事：画清知识结构，整理可核查的公开资源，保留证据和不确定性。

## v0.2 改变了什么

- 能力地图现在由 8 个开放领域、42 个可实践能力、12 个知识议题和 64 条明确关系构成。`supports` 只表示经常有帮助的方向，`complements` 表示互补；两者都不等于必修或固定顺序。
- 三个 Career Lenses 复用同一张地图。核心、重要和建议了解只说明某种生产语境中的关注程度；未纳入的节点仍然保留并保持可读，个人实践记录也继续独立存在。
- 成长资源把 20 个 Source 与 128 个具体 Work Item 分开建模，并提供 15 个无顺序资源主题与七维事实筛选。外部公开观察保留来源和日期，但不参与本站排序或评分。
- Innovation Atlas 变成一张按时间展开的全局网络。27 个节点和 25 条关系都引用证据；Roguelike 与 Metroidvania 只是高亮透镜，切换时不会删掉、移动或重新拥有任何实体。
- 一级导航只保留能力地图、职业方向、成长资源、创新变迁和关于本项目；Roadmap、Changelog、Devlog、Methodology 与 Contributing 集中到 About。
- 外观可以跟随系统，也可以显式选择浅色或深色。

## 为什么不是“标准答案”

这张地图主要继承游戏设计与 3A 生产经验，但它不把这一语境伪装成行业唯一标准。独立开发者通常会点亮更宽的能力多边形；同一职位在不同团队的责任也会不同。Career Lens 因此必须同时写明角色、生产环境、依据和局限，并且不能把用户状态合成为分数或职业适配判断。

资源收录同样不等于质量认证。项目会尽量核对链接、来源、语言、访问方式和主题关联，但不会把“进入目录”包装成推荐等级。有人想学习某个主题时，能够直接找到一批相关的具体内容，已经是这一阶段最重要的价值。

## 设计与工程教训

- “地图感”来自地域、节点和可解释关系，不来自给卡片加装饰。桌面与移动端可以使用不同布局，但必须表达同一组实体和关系。
- 高亮不能用低透明度把未选内容变得不可读。职业透镜和 Atlas 主题都只降低强调，完整上下文始终保留。
- 时间相邻不等于因果。Atlas 的有向边、无向结构对照、关系状态与原始文献必须分别表达；没有证据时宁可不连线。
- 资源语言要区分原始语言与用户实际可消费的 access version。Source 首页和具体 Work Item 也不能混成同一种对象。
- 浏览器 history、bfcache、无 JavaScript 与 GitHub Pages 子路径都属于产品事实，不能只靠静态截图判断。

## 下一步

v0.2 先验证这套结构是否真的让人更容易看见全貌、找到一个感兴趣的方向并进入具体资料。后续优先扩充内容覆盖、补齐资源语言版本和 Atlas 主题；完整英文界面、更多专业方向、账号或后台系统只在真实需求出现后再评估。
