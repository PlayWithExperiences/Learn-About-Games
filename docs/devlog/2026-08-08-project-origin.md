# Devlog 001：Learn About Games 从哪里来

- 日期：2026-08-08
- 阶段：产品定义

## 起点

这个项目始于一个持续出现的问题：如果一个人想学习游戏设计，他怎样知道这个领域包含什么、自己处于哪里，以及接下来应该学习什么？

网上并不缺少内容。GMTK、GDC、开发者频道、书籍、播客、课程和论文都提供了大量材料。真正缺少的是一张把这些材料连接到具体问题与能力的地图。

## 当前答案

Learn About Games 选择以知识与能力地图为学习主干：

- 新手可以先看全貌。
- 从业者可以标记当前状态并选择目标。
- 每项能力可以连接具体视频、章节、论文、练习和案例。
- 职业画像必须声明 AAA、独立团队或个人开发等生产语境。
- 地图只是参考，不是行业标准或资格认证。

资源收录会细化到单项内容。GMTK 是来源；讲解 Valve Playtest 的某一期视频才直接连接 Playtest 能力。重点资源还可以继续细化到时间戳或章节。

## 新增的历史视角

能力地图回答“如何学习”，但不能回答“游戏如何走到今天”。因此 Learn About Games 站内还会提供 Game Innovation Atlas，用时间轴、关系网络与证据展示机制、形式、技术和观念的出现、传播、变体、融合与复兴。它是同一产品中的历史知识板块，不是单独项目。

这里最重要的约束是：相似不等于传承。每条创新关系都要说明证据和确定程度；“第一款”默认只表示当前资料中最早有证据的实例。

## 为什么公开构建

项目既服务发起者自己的持续学习，也希望成为其他学习者可以使用和修正的公共资源。Roadmap 公开方向，Changelog 记录实际变化，Devlog 解释关键决策，GitHub Issue 和 Pull Request 承接外部贡献。

## 下一步

先建立一个可部署到 GitHub Pages 的最小站点，完成能力学习路径与资源导航的端到端样例。第一版同时列出 Game Innovation Atlas 的分类框架并提供一组有出处的种子内容；复杂时间轴、关系网络和大规模扩展在核心学习体验验证后推进。

## 第一个可见骨架

M0 先公开 9 个领域和每个领域的一个能力入口。领域使用结构分区，能力才是可进入的矩形节点，避免把不同实体画成同一种对象。Playtest 被明确标为下一步扩展，其余能力保留“学习路径尚未策展”的状态。

这一步同时建立了内容 Schema、引用校验和 GitHub Pages 子路径测试。它验证地图可以从结构化数据构建，但不声称资源、职业画像或 Atlas 种子已经完成。
