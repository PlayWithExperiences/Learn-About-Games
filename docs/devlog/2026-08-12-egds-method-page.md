# Devlog 007：为什么 EGDS 需要独立的说明页

能力地图已经使用 EGDS 组织体验设计，但方法本身长期只存在于地图节点、README 和零散说明中。读者可以看到“感受、理解、解构、重构”，却不一定知道这些节点从哪里来，也无法判断地图扩展内容与 EGDS 原始方法之间的边界。

## 当前模型以 PKM 为先

PlayWithExperiences Digital Garden 保存 EGDS 最新的概念组织。当前摘要采用两组互补结构：

- 体验因果链：情绪曲线 → 情绪体验 → 主观感受 → 客观原因 → 设计杠杆。
- 工作循环：感知 → 理解 → 解构 → 重构。

玩法与挑战、叙事、美学与表现是重构体验时可以共同使用的设计杠杆，不是互斥分类或固定部门边界。

2024 年已经发布的四篇 Emotional Game Design System 文章仍然重要。它们记录方法如何从叙事结构、系统构建、探索感分析走到 BOSS 战案例。这些文章是真实的历史版本，但不会反向限制 PKM 中继续发展的当前模型。

## 为什么是独立页面

只在 About 写一段长说明会让方法继续被项目资料淹没；把 EGDS 直接加入顶层导航，又会把方法说明与地图、资源、Atlas 等主要使用任务混成同一层。因此本轮新增 `/egds/`，并让 About 与能力地图提供上下文入口。顶层导航仍保持四项。

页面使用服务器渲染的有序文字结构，不依赖 JavaScript，也不为了“显得像系统”再造一张复杂图。它区分三类站内实体：EGDS Framework Node 表达方法结构，Capability 表达可实践能力，Knowledge Topic 表达理解背景。生产、协作、产品和更广语境是 Learn About Games 对方法应用边界的扩展，不被写成 EGDS 原始理论的全部内容。

## 没有做什么

- 没有复制整个 Digital Garden。
- 没有给 EGDS 增加认证、评分、必修顺序或唯一学习路径。
- 没有把四篇旧文章包装成当前模型的最终定义。
- 没有增加第五个全局导航项。

Learn About Games 保存可核查摘要、边界与原始链接。EGDS 最新的细节仍由作者 PKM 持续维护。
