# 把资源目录试成一条手感与反馈成长路径

## 背景

资源目录已经能按主题、能力、语言、媒介和访问事实筛选，但“有很多资料”不等于“知道先读什么”。用户提出一个更具体的方向：如果一个人想学习手感调优，能否把同一方向的资料按能力阶段整理成一条可以反复映照的成长路径。

这次只做一个窄切片，不把整座资源库改造成带分数的课程系统。第一条试验路径选择 `game-feel-feedback`，因为它已有足够大的真实资料集合，也能直接连接 EGDS 的体验设计框架。

## 路径结构

路径位于 `/resources/paths/game-feel/`，从目录中的 480 条相关资料稳定选出 100 条，分为六个阶段：

1. **感受**：观察身体、注意力、情绪和反馈差异，12 条。
2. **理解**：建立手感、反馈回路、视听表达与玩家视角的共同语言，18 条。
3. **解构**：从可观察体验追到规则、节奏、挑战和多模态呈现的客观原因，24 条。
4. **重构**：把诊断转成叙事、美学、玩法、挑战和反馈调优等设计杠杆，24 条。
5. **整合**：把局部调优放回系统、协作和批评语境，14 条。
6. **练习**：用小规模对照、记录和复盘把理解变成可重复的工作，8 条。

前四阶段在页面上明确展示 EGDS 的一一对应关系：

| EGDS 方法层 | 路径中的体验问题 |
| --- | --- |
| 感受 | 情绪体验：玩家实际感到了什么 |
| 理解 | 主观感受：玩家如何解释和命名这种感受 |
| 解构 | 客观原因：规则、节奏、挑战和表达如何造成它 |
| 重构 | 设计杠杆：可以怎样改动并验证新的体验 |

每一阶段都同时给出目标、练习、阶段产出和离开条件；资料仍可回到资源表，以搜索参数重新定位，不复制 Work Item 数据。

## 交互边界

页面使用原生 `details` 展开阶段，默认只打开第一阶段；每阶段先显示一小组资料，其余资料在阶段内部继续展开。路径不写入个人进度，不颁发证书、不计算分数，也不声称这是唯一学习顺序。资源目录原有的主题表、事实筛选、搜索和来源入口保持不变。

## 验证

- `tests/lib/learning-path.test.ts` 锁定六阶段、精确配额 `[12, 18, 24, 24, 14, 8]`、总计 100、EGDS 四层映射、资源唯一性和逆序输入稳定性。
- `tests/e2e/learning-path.spec.ts` 覆盖桌面、320px、无 JavaScript、阶段展开和回到资源表的搜索链接。
- 定向路径 E2E：6 passed。
- 全量 Vitest：183/183；`npm run check`：0 errors / warnings / hints；fresh build：143 pages。
- 全量 Chromium + mobile 回归：255 passed；22 个为项目已有的条件跳过。此前并发运行中的 Atlas 返回位置与 Career 对比度探针各出现一次超时，单独串行复跑均通过，未改相关代码。

本地预览保持在 `http://127.0.0.1:4321/Learn-About-Games/resources/paths/game-feel/`；仓库仍为 Private，未推送或部署。
