# Innovation Event Atlas 设计规格

## 目标

把 Innovation Atlas 的主语从“游戏作品”改为“品类演进中的创新事件”。用户先选择一个品类谱系，再沿时间顺序阅读定义、机制引入、结构转译和扩散事件；游戏只作为事件的承载作品与可核查材料出现。

## 核心语义

Atlas 中保留三类不同实体：

- `innovation`：事件。描述某个设计机制、结构或品类定义在何时以何种方式进入可观察的作品实践。
- `game`：承载作品。它证明事件曾在具体作品中被实现、传播或转译，但不再占据主时间线的主节点位置。
- `category` / 实验性节点：历史基础或硬件/原型上下文，只有被事件关系引用时进入事件详情，不伪装成事件本身。

事件不使用“绝对第一”措辞。事件角色只允许表达有证据支持的范围：

- `definition`：公开定义、命名或可辨识的品类形态出现。
- `mechanism`：一个可复用的设计机制被引入或明确化。
- `transformation`：已有机制被重新组合、扩展或转译。
- `diffusion`：机制进入更广作品实践或形成可辨识的谱系影响。

每个事件必须有：所属主题透镜、年份、机制说明、范围受限的摘要、至少一条 Evidence。事件→事件关系表达演进；事件→游戏关系表达承载作品。关系的 `summary` 必须区分“事件改变了什么”和“作品如何承载它”。

## 用户流程

1. 用户进入 `/atlas/`，看到品类透镜目录。
2. 选择一个透镜后，主地图只显示该透镜的事件时间线；默认隐藏普通游戏节点。
3. 时间线从左到右按事件年份排列，事件节点显示角色、年份和一行机制摘要。事件之间的有向边显示“定义→引入→转译→扩散”的演进关系。
4. 用户点击事件节点，右侧事件面板（窄屏为原生展开区）显示事件说明、承载作品、证据和相邻事件。再次点击当前事件、Escape、关闭按钮都能回到时间线，不需要“返回全图”作为唯一出口。
5. 用户可切换“显示承载作品”。打开后，游戏以较小的次级卡片贴在对应事件下方或事件详情内，不改变事件的时间轴位置和关系路由。
6. 没有足够事件证据的品类仍可选择，但显示明确的“待补证据”状态，不渲染空白线路或假节点。

## 视觉层级

- 事件节点：实线、较大、主色；节点标题先显示事件名称，不显示 `Game` 前缀。
- 演进关系：实线箭头，方向和关系类型可读。
- 承载作品：较小、低强调、虚线边框；默认不参与主图连线。
- Evidence：只在事件面板和集中索引中出现一次，引用链接返回原事件。
- 透镜按钮仍保持当前互斥语义；选择透镜只改变事件过滤与强调，不复制第二张地图。
- 地图模式继续支持缩放/平移，但事件时间线在默认 fit 状态下必须可读；窄屏使用关系等价的原生大纲。

## 数据边界

首个完整样板为 FPS 谱系。它至少包含“第一人称射击视角公开定义”“空间/武器机制扩展”“快速垂直移动或关卡结构转译”“网络/多人空间扩散”等事件，并为每个事件列出 Doom、Wolfenstein 3D、Quake、Half-Life 等承载作品及证据。其他谱系先迁移现有可信创新节点，再逐条补事件与证据；未核验的关系不自动生成。

不引入评分、排名、学习顺序或职业适配结论；不恢复已退休的 Domains / mapGroups ontology。现有作品和证据 ID 保持稳定，迁移只增加事件字段、事件关系和显示索引。

## 验收标准

- 选择 FPS 透镜后，主图主节点均为事件，事件数量和事件关系数量可由 DOM 与纯 helper 一致计算。
- 事件详情中承载作品至少有一个可达链接；普通游戏不出现在默认事件主节点集合中。
- 事件详情可以通过点击、再次点击、Escape 和关闭按钮离开，且恢复原画布位置、页面位置和焦点。
- “显示承载作品”只改变次级作品可见性，不改变事件节点 ID、年份、坐标或事件关系。
- 无事件的透镜显示明确空状态；无 JavaScript 时事件大纲、承载作品、证据链接仍可读，交互控件禁用并说明。
- Light/Dark、1440px、1024px、320px 均无页面横溢出；事件标题不产生一两个字的孤立行。
