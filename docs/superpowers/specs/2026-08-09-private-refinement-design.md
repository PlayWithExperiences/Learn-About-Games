## 1. 本轮目标

本轮不扩张知识内容规模，只修复 v0.2 已被实际使用暴露出的五个核心体验问题：

1. 能力地图虽然包含 8 个领域、42 个能力、12 个知识议题和 64 条关系，但领域与关系同时等权出现，缺少可读主干。
2. 深色主题中的 Career Lens 主要依赖暗色描边，核心、重要与建议了解的差异不够明显。
3. Work Item 使用双列布局，在宽屏上横向跨度过大，阅读单条资源时视线移动过远。
4. Innovation Atlas 的桌面画布只能横向滚动，不能缩放、拖拽平移或快速回到全图。
5. Atlas 节点详情缺少搜索和明确的名称／时间排序选项。

本轮完成后，仓库仍保持 Private。重新公开是独立发布步骤，需要重新启用 Pages workflow 并执行线上验收。

## 2. 第一性原理与不变量

### 2.1 用户要完成的决定

- **看全貌**：先知道游戏设计相关能力由哪些主要方向组成，再进入具体领域和节点。
- **找方向**：选择一个职业语境后，能立刻分辨该画像关注什么，同时仍能看到未收录能力。
- **找资源**：快速扫描标题、来源、关联原因和访问事实，而不是在宽大卡片之间来回移动视线。
- **探索变迁**：既能看到全局时间结构，也能放大检查局部关系，并从索引定位具体实体。

### 2.2 不变量

- 地图层级只表达**归属和阅读结构**，不表达价值排名、难度或固定成长顺序。
- `supports` 与 `complements` 仍是跨节点真实关系，不能因为改成思维导图外观而伪装成父子关系。
- Career Lens 不生成分数、差距、完成率或职业适配结论。
- 资源不增加站内评分、精选、审核等级或统一学习路径。
- Atlas 横轴继续只表达时间；缩放和平移不能改变节点、关系、位置或主题归属。
- 无 JavaScript 时，完整内容、链接和关系文字仍可访问；依赖脚本的控件保持禁用并说明。

## 3. 能力地图：分层思维导图 + 按需关系网

### 3.1 舍弃的两种方案

**继续使用地域网格，只加粗标题**：改动小，但 8 个领域和 64 条线仍然同时竞争注意力，无法建立主次。

**改成严格树状图**：主干很清楚，但会错误暗示能力只有一个父节点，或者存在唯一成长路径。

### 3.2 采用的结构

桌面地图改为从左向右阅读的分层思维导图：

```text
Expertise Map
├─ 体验与玩家
├─ 玩法、空间与表达
├─ 研究、原型与交付
├─ 协作、领导与方向
└─ 产品、市场与更广语境
```

五条主干覆盖现有 8 个 Domain，且每个 Domain 只属于一条主干：

| 主干 | Domain |
| --- | --- |
| 体验与玩家 | 体验与玩家 |
| 玩法、空间与表达 | 玩法、系统与手感；关卡与空间；叙事与表达 |
| 研究、原型与交付 | 研究、验证与数据；原型、生产与迭代 |
| 协作、领导与方向 | 协作、领导与方向 |
| 产品、市场与更广语境 | 产品、市场与批判语境 |

这些主干是稳定的**地图阅读分组**，不是新的 Capability、Domain 或 Career Lens，也不复制 catalog 节点。

### 3.3 视觉层级

- `Expertise Map` 根节点位于左侧，是唯一一级入口。
- 五条主干使用最强的结构线和大标题。
- Domain 是第二级分支，标题和边界弱于主干但强于节点。
- Capability 是主要叶节点，保持可直接进入详情。
- Knowledge Topic 使用不同形状和“知识议题”文字，不与 Capability 共用外观。
- 主干连接与 Domain 归属线持续显示，承担“地图骨架”。
- `supports` 与 `complements` 默认退到背景；键盘聚焦、鼠标悬停或选择节点时，才增强该节点的直接关系和端点。
- 关系增强时仍用实线箭头表达 `supports`、虚线无箭头表达 `complements`，不改变原有语义。

默认画面首先回答“有哪些主要方向”，聚焦状态再回答“这个能力和什么相关”。

### 3.4 数据与布局合同

新增一份明确的 Map Group 数据，而不是把分组名称硬编码在 CSS：

- `id`
- 中英文名称与摘要
- `order`
- `domainIds`

构建期验证：

- 恰好覆盖所有 Domain。
- Domain 不重复、不遗漏。
- Map Group ID 唯一。
- 分组顺序稳定。

布局 helper 根据根节点、Map Group、Domain 和节点的层级生成稳定坐标；内容刷新不能随机重排。现有 `supports` / `complements` 数据继续决定跨节点关系，不参与父子层级生成。

移动端继续使用关系等价大纲，但先显示五条主干，再进入 Domain 与节点；不把桌面大图缩小塞进 320px。

## 4. Career Lens：深色主题下的明确覆盖层

应用 Career Lens 后，全部 Capability 保持可读、可点击。三档关注程度使用颜色之外的稳定编码：

| 档位 | 节点编码 |
| --- | --- |
| 核心 | 高对比强调填充、2px 实线边框、持续显示“核心”标签 |
| 重要 | 轻强调填充、2px 实线边框、持续显示“重要”标签 |
| 建议了解 | 普通表面、2px 虚线边框、持续显示“建议了解”标签 |
| 未收录 | 正常文字与不透明表面、较弱中性边框，不隐藏、不降低整节点 opacity |

深色主题中，核心节点必须与画布表面形成明确的表面差异；重要与建议了解不能只使用相近深蓝色。标签、线型和边框粗细在浅色与深色中保持同一语义。

摘要列表与地图节点必须同步：选择画像、清除画像、历史恢复后，两处显示相同档位和状态。责任范围继续只在摘要中以文字表达，不再增加另一套节点颜色。

## 5. 成长资源：单列紧凑编辑行

Source 与 Work Item 仍是不同实体。Work Item 从双列网格改为每项占一行的单列编辑列表。

桌面单行分为三个信息区：

1. **主信息**：标题、Source、简短关联原因。
2. **事实**：媒介、原始语言、可消费语言与主题标签。
3. **访问**：免费／付费／订阅、合法入口与检查日期。

外部评价事实和较长的版本说明进入原生 disclosure，避免把每条结果撑成长卡片，但不删除数据。列表内容宽度使用当前正文阅读宽度，不铺满超宽屏。

移动端把同一行的三个信息区垂直排列；不引入横向滚动、表格截断或只在 hover 时出现的操作。

筛选、URL 参数、catalog 顺序、no-JS 完整输出和“不按外部评价排序”的合同保持不变。

## 6. Innovation Atlas：可控视口

### 6.1 控件

桌面 Atlas 在画布上方增加一组本地控件：

- 适应全图
- 放大
- 缩小
- 重置为 100%
- 当前缩放比例

缩放范围固定为 50%–200%，按钮步进 25%。“适应全图”根据当前 viewport 与固定网络画布计算比例，允许用户先看整体结构；“重置”回到 100% 并恢复网络起点。

### 6.2 平移与输入方式

- 保留 viewport 自身滚动位置作为唯一平移状态。
- 鼠标或触控拖拽通过 Pointer Events 改变 scrollLeft / scrollTop。
- 方向键在画布聚焦时平移。
- `Ctrl/Command + wheel` 缩放，普通滚轮继续执行自然滚动，不劫持页面。
- 缩放以当前 viewport 中心为锚点，避免每次放大跳回左上角。
- `prefers-reduced-motion` 下不使用平滑动画。

画布尺寸、节点坐标和关系路径仍来自同一固定布局。缩放只改变显示比例，不重新运行布局，也不引入 force graph 或第三方图形依赖。

移动端继续以时期大纲为主要表示；不把缩小后的桌面网络强塞进窄屏。搜索与排序仍在移动端可用。

### 6.3 无 JavaScript

无 JavaScript 时画布保持 100% 原生滚动，缩放控件禁用并显示说明；移动时期大纲、节点详情、关系详情与 Evidence 仍完整可读。

## 7. Atlas 节点索引：搜索与排序

节点详情索引前增加：

- 搜索框
- 排序选项：按时间、按名称
- 当前结果数量

行为定义：

- 默认按 `startYear` 升序，年份相同再按名称和 ID 稳定排序。
- 按名称使用可预测的中英文 `Intl.Collator`；不改写实体标题。
- 搜索匹配中英文标题、摘要与已公开 Tag。
- 搜索只筛选节点索引，并在全局网络中增强匹配节点、弱化未匹配节点；不删除网络实体，不改变主题透镜、关系数量或位置。
- 清空搜索恢复完整索引和当前主题透镜。
- 搜索没有结果时显示明确空状态和“清除搜索”操作。
- 节点索引排序不影响关系索引和 Evidence 索引。
- 查询与排序不写入 catalog，不持久化到 localStorage；本轮不增加 URL 状态，避免把临时浏览控制升级成公共链接合同。

无 JavaScript 时完整节点索引按时间输出，控件禁用并说明。

## 8. 组件边界

- `CapabilityMap`：只负责地图结构、关系聚焦与移动大纲。
- `CareerExplorer`：只把 profile projection 应用到现有地图，不拥有地图布局。
- `ResourceResults`：只负责 Source / Work Item 的结果呈现，不改变筛选语义。
- `AtlasNetwork`：组合固定布局、视口控制、主题透镜与详情入口。
- 新的纯 helper：负责缩放边界、中心锚点换算、节点过滤和稳定排序；DOM controller 只读写视口与可见状态。

不引入全局状态管理器、canvas renderer、图布局依赖、搜索服务、数据库或动画库。

## 9. 验收标准

### 能力地图

- server HTML 只有一个根、5 条主干、8 个 Domain、42 个 Capability、12 个 Knowledge Topic。
- 所有 Domain 恰好属于一条主干。
- 默认截图能先读出五条主干；64 条关系不再与主干等权竞争。
- 聚焦任意 Capability 时，只增强它的直接 `supports` / `complements` 关系和端点。
- 1440px 与 320px、Light 与 Dark、no-JS 均保留全部节点入口且无页面横向溢出。

### Career Lens

- 深色主题的三档画像在填充、边框和标签上都可区分。
- 关键文字达到 WCAG AA；非文本边界达到至少 3:1。
- 未收录节点整节点 opacity 保持 1。
- 应用和清除画像后，地图与摘要状态一致，不产生评分。

### Resources

- desktop Work Item 容器为单列；每项结果只有一个主行。
- 128 个 Work Item、20 个 Source、筛选参数和 catalog 顺序不变。
- 320px 无横向溢出；no-JS 全部结果和访问链接仍可达。

### Atlas

- 50%、75%、100%、125%、150%、175%、200% 控制边界稳定；不会超出范围。
- 适应全图后可看到整个网络边界；重置恢复 100%。
- 拖拽、按钮、键盘和 Ctrl/Command + wheel 均可操作，且缩放前后焦点实体保持可定位。
- 搜索能匹配中英文标题／摘要／Tag；按时间与按名称排序稳定。
- 搜索和排序前后仍有 27 个网络节点、25 条关系、40 项唯一 Evidence；主题透镜只改变强调。
- 320px 使用完整时期大纲；no-JS 内容与关系详情不减少。

### 全站

- Astro check、Vitest、fresh build 与完整 desktop/mobile E2E 全绿。
- 视觉验收至少覆盖 Map、Career、Resources、Atlas 的 1440px/320px、Light/Dark，以及 Career 与 Atlas no-JS 状态。
- 重新公开前另行运行 GitHub Pages workflow 与匿名线上契约检查。

## 10. 明确不做

- 不在本轮新增资源、Atlas 节点、职业画像或英文完整界面。
- 不把 Map Group 解释为学习路径或组织架构标准。
- 不为职业画像增加雷达图、能力差距或推荐算法。
- 不为资源增加站内评分、排名、审核状态或自动推荐。
- 不为 Atlas 增加 force-directed 自动布局、无限画布、3D、迷你地图或服务端搜索。
- 不在核心体验验收前恢复 Public 或 Pages。
