# 手感与反馈成长路径：试验设计

## 目标

在现有成长资源目录之外，提供第一条可执行的学习路径。试验方向是“手感与反馈”，用一百条已经进入资源库的资料，说明从观察体验到重构设计的学习顺序，同时保留资源库原有的无顺序浏览方式。

这不是评分、证书或唯一课程表。路径是一个可复核的推荐顺序；每个阶段都能回到原始 Work Item、Source、能力和知识主题。

## 核心模型

路径分为六个阶段：

1. 观察与描述（12 条）：记录输入、动作、反馈和身体感受，不急于解释原因。
2. 理解体验（18 条）：把体验放入知觉、注意、情绪和视听反馈的语境。
3. 解构问题（24 条）：从体验现象拆到规则、时序、节奏和反馈回路。
4. 重构设计（24 条）：用输入、运动、挑战、动画、声音和镜头等杠杆提出改动。
5. 系统整合（14 条）：把局部手感放回情绪弧线、表达和团队协作中检查。
6. 综合实践（8 条）：完成一次可比较的手感实验，并整理证据与复盘。

前四阶段明确呈现 EGDS 对应关系：

| EGDS 操作 | 体验设计对应 |
| --- | --- |
| 感受 | 情绪体验 |
| 理解 | 主观感受 |
| 解构 | 客观原因 |
| 重构 | 设计杠杆 |

## 页面行为

- 路由为 `/resources/paths/game-feel/`，从资源页的“学习路径”入口进入。
- 六个阶段使用原生 `details`，默认只打开第一阶段；没有 JavaScript 时仍可逐阶段展开。
- 每阶段展示目标、练习、阶段产出、退出条件和资料数量；资料列表紧凑排列，长列表可在阶段内继续展开。
- 每条资料链接回资源库的搜索结果，不复制资源详情，不创建第二份事实数据。
- 不保存分数或学习结论。第一版不引入个人进度状态，避免把推荐顺序误当能力认证。

## 约束

- 100 条资料必须来自 `game-feel-feedback` 主题，ID 不重复，且每条有合法 Source、至少一个能力或知识主题。
- 选择器按资源 ID 做稳定排序，输入顺序变化不能改变阶段分配。
- 中文标题优先，缺少中文标题时显示英文；不因补齐数量而虚构资料或证据。
- 桌面与 320px 移动视口均不能产生页面横向溢出；颜色和分隔线只用于层级，不增加装饰性面板。
