# EGDS 方法介绍页设计

## 目标

为 Learn About Games 增加一个独立的 `EGDS｜情感化游戏设计系统` 页面。它解释能力地图采用的作者方法基础，同时把当前 PKM 模型与已经发布的历史文章明确区分。

## 事实来源与版本边界

- PlayWithExperiences Digital Garden 是当前 EGDS 工作模型的主要来源。页面正文以其中的当前概念链与方法循环为准。
- 2024 年发布的四篇 Emotional Game Design System 文章是真实的历史版本。它们用于解释方法如何形成，不反向限制当前模型。
- Digital Garden 中的独立笔记仍会继续变化。Learn About Games 只发布可核查摘要和原始链接，不复制整套 PKM，也不宣称自己是第二个权威副本。
- EGDS 是 PlayWithExperiences 提出并持续修订的作者方法，不是行业标准、资格认证、必修顺序、唯一学习路径或个人评分系统。

## 当前模型

页面以两个互补结构解释当前 EGDS：

1. 体验因果链：`情绪曲线 → 情绪体验 → 主观感受 → 客观原因 → 设计杠杆`。
2. 工作循环：`感受 → 理解 → 解构 → 重构`。

这两组结构不是彼此平行、互不相干的列表。情绪曲线是整体体验入口；后续四层与工作循环一一对应：

- 感受 ↔ 情绪体验；
- 理解 ↔ 主观感受；
- 解构 ↔ 客观原因；
- 重构 ↔ 设计杠杆。

页面必须直接写出这四组对应关系。响应式布局可以改变列数，但不能只靠颜色、相对位置或视觉连线传达配对，也不能把情绪曲线错误配给工作循环中的某一步。

设计杠杆以玩法与挑战、叙事、美学与表现作为三类入口。页面说明它们不是互斥分类，而是重构体验时可共同使用的设计手段。

## 与能力地图的关系

- EGDS 页面解释方法本身。
- 能力地图借用 EGDS 的作者结构组织游戏设计及相邻能力，但地图不是 EGDS 全文。
- `EGDS Framework Node` 表达方法结构；`Capability` 表达可实践能力；`Knowledge Topic` 表达理解背景。
- 生产、协作、产品与更广语境是 Learn About Games 对方法应用边界的扩展，不冒充为 EGDS 原始理论的全部内容。

## 信息架构

### 独立路由

新增 `/egds/`，使用现有 `BaseLayout`、主题与 base path 规则。

### 页面顺序

1. 简洁开场：EGDS 是什么、解决什么问题、当前权威来源在哪里。
2. 当前模型：以情绪曲线作为整体入口，再明确展示体验因果链后四层与四步工作循环的一一对应。
3. 如何使用：从一个可观察的体验问题追到设计杠杆，再回到可验证的重构。
4. 与能力地图的关系：方法结构、能力、知识议题三类实体的边界。
5. 演进记录：四篇正式文章按发布日期列出，说明各自作用。
6. 当前知识库：链接 Digital Garden，并说明它比历史文章更新、仍会继续修订。
7. 方法边界：作者方法、非标准、非评分、非唯一道路。

### 入口

- “关于本项目”在资料导航之前增加一个 EGDS 方法入口，并把 EGDS 作为该页面的主要方法基础之一。
- 能力地图介绍区增加“了解 EGDS 方法”上下文链接。
- 顶层主导航保持能力地图、成长资源、创新变迁、关于本项目四项，不增加第五项，避免把方法说明与主要使用任务混为一层。

## 视觉方向

Reading this as: 面向游戏设计学习者和实践者的作者方法说明页，采用克制、可核查的编辑型信息设计，并延续现有 Learn About Games 原生 CSS 系统。

- `DESIGN_VARIANCE: 5`：有清晰节奏和轻微不对称，但不做实验型编排。
- `MOTION_INTENSITY: 2`：只保留现有 hover、focus 和主题切换，不增加滚动动画。
- `VISUAL_DENSITY: 5`：比营销页紧凑，比资料表宽松；一屏能看到方法主链和下一段入口。
- 延续现有单一蓝色强调色、同一圆角体系、Light/Dark 主题和中文优先文字。
- 不生成新插画。用户明确偏好文字优先，而该模型能由有序文字、方向符号与真实来源链接准确表达。
- 长来源集合使用四项历史文章网格和一个独立 PKM 区，不做逐行长表。

## 可访问性与无 JavaScript

- 页面所有核心内容由服务器渲染，不依赖 JavaScript。
- 主链使用有序列表并保留可读的线性文本；四组对应关系同时具有可读文字，不用只靠颜色或位置传达顺序或配对。
- 外部链接使用明确标题与来源说明。
- 1440px、320px、Light、Dark 和 no-JS 均需无页面横向溢出。
- 标题层级、landmark、焦点样式与 base path 链接由 E2E 锁定。

## 非目标

- 不把整个 Digital Garden 镜像进仓库。
- 不为 EGDS 建立独立评分、课程、认证或版本号。
- 不在本轮扩写能力地图节点、学习资源或 Innovation Atlas 数据。
- 不新增全局导航项。

## 验收标准

- `/egds/` 返回 200，页面包含当前五层因果链、四步工作循环、四组一一对应关系、三类设计杠杆、地图关系、四篇历史文章和 Digital Garden 入口。
- 页面明确 PKM 是当前模型来源，历史文章是演进证据。
- About 与 Map 都能通过 base-path-safe 链接进入 `/egds/`。
- 页面没有把 EGDS 表述为行业标准、必修顺序、唯一道路或评分系统。
- 无 JavaScript 仍完整可读；1440px 与 320px Light/Dark 无横向溢出。
